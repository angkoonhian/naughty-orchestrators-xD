# Migration Guide

When bootstrap detects an existing `CLAUDE.md` not generated by this skill, it enters Migrate mode.

## Phase 1: Read existing state

- Read `<root>/CLAUDE.md` completely.
- Catalog `docs/agents/` (or equivalent agent directory) contents.
- Identify existing patterns: Leads, cross-cutting agents, DA, personas, task agents, dispatch tables.

## Phase 2: Map existing → new universal slots

| Existing pattern | New universal location | Action |
|---|---|---|
| Old monolithic `devils-advocate.md` | `docs/agents/cross-cutting/da-lead.md` + `docs/agents/da/core/*.md` | Split: routing → da-lead, evaluation → core critics |
| Existing `qa-lead.md` (+ sub-agents) | preserved + wrapped by new `qa-delegator.md` | qa-lead stays; qa-delegator added |
| Existing `architect.md` | `docs/agents/cross-cutting/architect.md` | Preserved as-is |
| Existing project Leads (api-lead, admin-lead, etc.) | preserved | Add sub-specialist stubs if missing; add adaptive Tier 2 if threshold hit |
| Existing personas | `docs/agents/personas/*.md` | Preserved as-is |
| Existing task agents | `docs/agents/task-agents/*.md` | Preserved as-is |

## Phase 3: Add new universal pieces

These don't exist in legacy systems and are added unconditionally:

- `docs/agents/cross-cutting/pre-impl-validator.md`
- `docs/agents/cross-cutting/post-impl-validator.md`
- `docs/agents/cross-cutting/qa-delegator.md` (wired to detected QA infra)
- `docs/agents/validators/pre-impl/*.md` (6 files)
- `docs/agents/validators/post-impl/*.md` (5 files)
- `docs/agents/da/core/*.md` (7 universal critics — from split of old DA + skill-shipped defaults)
- `docs/agents/da/<project-slug>-pack/*.md` (inferred platform-pack critics)

## Phase 4: Conflict resolution

Surface conflicts to user via AskUserQuestion. Examples:

- "Existing CLAUDE.md has its own impact-tier table. Keep as-is, or replace with skill's universal version?"
- "Existing devils-advocate.md has unique evaluation criteria not in the universal core 7. Preserve as platform-pack additions or merge into core?"
- "Existing dispatch table maps `bug-fix` to a custom workflow. Preserve, or replace with skill default?"

For each conflict, user picks: **keep existing** / **replace with new** / **preserve both, mark for review**.

## Phase 5: Backup

Before any modification:

```
.claude/orchestration.backup-<YYYY-MM-DD-HHMMSS>/
├── CLAUDE.md                    # Original root
├── docs/agents/                 # Complete copy of existing agent tree
└── manifest.yaml                # What was backed up + restore command
```

A single command restores from the backup:

```bash
/orchestrate restore .claude/orchestration.backup-<timestamp>/
```

## Phase 6: Generate

Write new files. Existing files modified only if user approved replacement. Never silently overwrite.

## Phase 7: Report
